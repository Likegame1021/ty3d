# 河南农村童年冒险：资产制作流程 v1.1

更新日期：2026-09-27。用户已确认：**Windows 电脑优先**。

本文件优化资产生产工序，不改变[设计档案 v1](design-baseline-v1.md)的人物与关卡设定。下列尺寸、预算与技术选择是首个资产的试行建议。后续已启动首个样件制作，实际状态以[样件计划](first-playable-plan.md)和[QA实测](qa/first-playable-results.md)为准；未安装桥接插件，采用 API 下载结果再导入 Blender。

## 1. 推荐主流程

**资产需求卡 → 我制作独立参考图 → Meshy 生成带贴图模型 → Blender 结构预检 / 必要修整 → Meshy 绑定与基础动画 → Blender 权重、动作与材质精修 → GLB → Godot 验收。**

穿插两次提前验证：

- 结构预检后，先将静态模型放到 Godot 的目标斜俯视镜头下，检查尺寸、颜色、轮廓与遮挡。
- 基础动画完成后，先验证移动与一次攻击，再补齐动作库。

预检合格的模型直接继续，不为流程而强行重拓扑。需要修网格时再做 Blender → Meshy 回传。

| 阶段 | 主要工作 | 通过后再做什么 |
| --- | --- | --- |
| 参考图 | 同一角色、同一比例、同一姿态，四向细节一致 | 生成模型 |
| 静态模型 | 检查手脚分离、轮廓、尺度、关节网格、UV 与贴图 | 正式绑定 |
| 骨架 | 测试肩肘、胯膝、脚底和包带的变形 | 扩充动画 |
| 游戏导入 | 检查移动、攻击、挂点、昼夜、重导入与性能 | 批量制作同类资产 |

## 2. 出图：把概念板变成生产输入

角色沿用正面、左侧、背面、右侧 T-Pose 方向。四张独立生产图已保存在 `art/characters/boy/references/v001/`，提示词和修订记录同时归档。

- 从同一个角色母稿派生多视图；不把四次独立生成的不同男孩拼在一起。
- 每张只有一个完整角色，背景简单、光照均匀，无标题、尺寸线、地台、场景或持握武器。
- 统一头身比例、发型、包的位置、背带走向、围巾结、衣服补丁、鞋袜与脚底基线；侧视图不能直接镜像冒充另一侧。
- 保持腋下、双腿、手与身体间隙清楚；不追求极细的发丝、悬空线头或复杂布条。
- 出图阶段就缩小到预期游戏画面中的角色大小，检查黑发、红围巾与斜包是否仍可辨认。

Meshy 多图接口目前接受 1～4 张同一对象的不同视角图片；当前模型版本以首张为主要正面视图。使用四张一致的图，不把说明海报当成单体建模输入。具体接口参数在执行时以官方文档与所选模型版本为准。[官方多图接口](https://docs.meshy.ai/en/api/multi-image-to-3d)

## 3. 绑定前处理结构，绑定后精修动作

### 绑定前：决定模型能否动得自然

重点检查手臂是否粘住身体、手指是否异常、腋下与胯部是否封死、衣物是否穿插、肩肘膝是否有足够合理的网格，以及法线、UV、材质和实际尺寸。

- Remesh 只在确有需要时使用；面数降低或变成四边形，不等于关节已经适合弯曲。
- 重拓扑、主要减面、改身体比例、分离零件、整理对象变换，应尽量在正式绑定前完成。
- 若修改了 UV 或网格导致纹理不再匹配，先修复 / 重烘焙贴图，再交给 Meshy 绑定。
- 保留未经修整的原始模型，方便比较与恢复。

Meshy 当前自动绑定主要面向肢体清晰、带贴图的标准双足人形；自定义输入支持带贴图 GLB，通过 `model_url` 提供时要求角色朝向 +Z，并提供 `height_meters`。因此主角可以先试，田鼠、非人形巡游怪及特殊结构 Boss 需要另行评估绑定方案。[官方绑定接口](https://docs.meshy.ai/en/api/rigging)

若 Blender 已修改模型，绑定应使用修订后的 GLB；不能继续引用旧生成任务而把修订丢掉。身体结构合格、没有修改的模型可直接沿用原任务。

### 绑定后：保留稳定骨架

修肩膀、肘部、膝盖、包带的权重，以及脚滑、穿模、动作节奏、贴图与法线。骨架层级、名称、静止姿势稳定后再扩充动画。

需要再次大幅改比例或拓扑时，回到绑定前版本，重新绑定或转移权重并复验。不要指望对绑定模型直接大幅减面后，已有动作自然全部保持正确。

## 4. 主角本体、装备与动画分开管理

- 树枝、弹弓、玉米枪作为独立道具，在游戏里挂到手部挂点；不与手焊成同一个生成模型。
- 衣服与身体可作为同一蒙皮主体；包体可按实际运动需要挂到骨骼，背带需检查随躯干变形，不能简单将整条背带当刚性物件。
- 红围巾保留视觉记忆点；首版可采用简化固定形态，先验证是否穿模，动态布料不是首个样件的前置条件。
- 复用同一次绑定得到的骨架，避免每个动作各生成一个结构不同的角色。

先做 **Idle、Walk、Run、Tree Branch Attack** 四个动作验证完整流程，再补齐原设计第一阶段的 Hurt、Interact、Pick Up。原第一阶段七项需求保持不变。

基础待机与走跑可从现成动作起步；树枝击打、弹弓瞄准、推板车、抓泥鳅等动作需要按儿童比例、道具握法与玩法节奏验收，必要时在 Blender 调整。

当前 Meshy 动画接口支持同一 `rig_task_id` 选择多段动作，`action_ids` 一次最多 10 个，返回含多个独立片段的文件。应先选中适合的动作再提交；批量返回文件不代表只按一段动作计费。绑定结果若已带可用走跑动画，先验收复用。[官方动画接口](https://docs.meshy.ai/en/api/animation)

## 5. Meshy → Blender：减少搬运，保留版本

日常人工操作可选官方 **DCC Bridge**，从 Meshy 网页发送到 Blender，动画模型也受支持；API 制作则在任务完成后下载到本地版本目录，再导入 Blender。两条路径最终都进入同一个资产母版。[官方桥接说明](https://docs.meshy.ai/en/webapp/plugins/blender/introduction) · [动画模型支持](https://docs.meshy.ai/en/webapp/plugins/blender/animated-models)

当前官方安装页列出的 Bridge 条件为 Blender 4.2.6+、Meshy Pro 或以上账户；新版 Bridge 不需要填写 API key。已有 API 余额不能据此证明账户满足 Bridge 套餐条件，安装前需核对本机版本与账户。[官方安装与要求](https://www.meshy.ai/integrations/blender)

这里的“同步”按导入新版本理解，不预设 Blender 手工修改会自动双向回写到 Meshy。每次新结果先作为版本保存，避免覆盖已经修好的权重与动作。

本项目保留 `.blend` 母版，以 `.glb` 作为主要游戏交付格式；FBX 可用于确有需要的动画中转，静态无骨骼用途才考虑 OBJ。Godot 支持直接导入 `.blend`，但内部需要调用本机 Blender 转换，因此当前建议 GLB 作为稳定交付边界。[Godot 支持格式](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

## 6. Blender → Godot 的试行约定

以下均为项目建议，首个样件通过后再作为固定规范：

| 项目 | 首轮约定 |
| --- | --- |
| 尺寸 | 1 单位对应 1 m；主角先用 1.2 m 作为 1.1～1.3 m 范围内的试验值 |
| 原点 | 角色与地面道具以脚底 / 底部中心为基准；铰链门、车轮按运动轴设置 |
| 变换 | 绑定前整理缩放与旋转；已绑定资产不盲目分别 Apply 骨架和网格 |
| 朝向 | 常规 Blender glTF 工作流中角色面向 −Y；导出后按 GLB / Meshy 自定义输入与 Godot 角色资产的 +Z 前方验收，避免重复补偿旋转 |
| 动画 | 使用明确的片段命名；首轮采样基线 30 fps，Idle / Walk / Run 循环，攻击与受击不循环 |
| 移动 | 第一版走跑采用原地动画，由 Godot 控制角色位移；攀爬、翻越以后单独评估根运动 |
| 导出 | 导出实际需要的网格、材质、变形骨骼及必要根节点；将控制器 / 约束产生的动作结果采样成可导出的关键帧 |
| 材质 | 使用可由 glTF 表达的标准材质，复杂程序材质需烘焙或在 Godot 中重建 |
| 光照 | 贴图尽量保留物体本色，避免把强烈太阳阴影烘死；白天 / 夜晚氛围在 Godot 灯光中验证 |

Blender 导出器会处理坐标系转换；不要因为 Blender 与 Godot 的上轴不同，凭感觉给角色再旋转一次。导出模式与 Action / NLA 设置按实际安装版本检查，验收文件是否包含全部预期片段。[Godot 导出约定](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/model_export_considerations.html) · [Blender glTF 参考手册（4.4）](https://docs.blender.org/manual/en/4.4/addons/import_export/scene_gltf2.html)

Godot 中用独立角色场景承载 `CharacterBody3D`、碰撞体、脚本、`AnimationTree` 和挂点，将导入模型作为其子场景。这样更新 GLB 时，可保留玩法层；若改了骨骼名称或节点路径，仍须修正动画轨道与挂点引用。角色移动碰撞优先简单胶囊，不直接使用高精度蒙皮网格作移动碰撞。[导入与场景继承](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/import_configuration.html) · [AnimationTree 与根运动](https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html)

不同角色共享动作时，不能只对齐骨骼名字，还要处理层级、静止姿势、比例与轨道路径。先跑通同一骨架，NPC 复用阶段再使用 BoneMap / SkeletonProfileHumanoid 等重定向流程。[Godot 动画重定向](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html)

## 7. 角色、道具、植被分三条生产线

| 资产 | 建议流程 | 项目重点 |
| --- | --- | --- |
| 主角 / 人形 NPC | 参考图 → Meshy → 结构预检 → 绑定动画 → Blender 精修 → Godot | 轮廓与动作变形 |
| 简单模块、农具、院墙 | 参考图 → Meshy 或 Blender 直接建模 → 模块与碰撞整理 → Godot | 拼接尺寸、原点、材质复用；不要全部重复生成 |
| 玉米、杂草、叶片 | 少量基础形态 → Blender 整理低复杂度网格和共用贴图 → Godot 地块实例化 | 成片性能、风摆、受扰动可读性 |

一组围栏或院墙先做好可重复的直段与转角；简单几何直接在 Blender 制作可能比 AI 生成后修尺寸更省事。玉米先验证一株和一个小地块，再扩展变体。

玉米计划按地块使用 MultiMesh，并按网格与材质变体分批。MultiMesh 始终不逐株裁剪，按地块拆分可获得地块级裁剪，避免一个大包围盒覆盖整片田。风摆、敌人扰动、遮挡与采摘响应需要 Godot 侧单独实现，不是模型文件自带功能。[MultiMesh 文档](https://docs.godotengine.org/en/stable/classes/class_multimesh.html)

大多数玉米不逐株配置骨架或刚体；可以交互的少量植株与普通装饰植株分开处理。区域声响 / 晃动强度用于实现“小动物轻微、普通怪物明显、大型敌人剧烈”的既定视觉语言。

性能检查同时看帧时间、材质数、透明叶片的重叠与阴影开销，不能只统计面数。角色可见性与玉米遮挡规则需在目标斜俯视镜头下试验，保留“看不清，但能感觉到”的玩法，而非把整片玉米全部透明化。

## 8. Windows 首轮资源预算建议

以下不是引擎上限，也不是性能保证；尚未确定最低配置，先用代表性场景测量再调整。

| 资产 | 初始目标 |
| --- | --- |
| 主角 | 约 1.5～2.5 万三角面；主要贴图 2K；尽量 1～3 个材质 |
| 常见小道具 | 按画面大小先尝试数百至几千三角面；共用 512～1K 贴图或图集 |
| 成片植被 | 优先减少单株复杂度与材质切换；数量、阴影和叶片覆盖面积一起实测 |

统计导出后的实际三角面和材质开销；Meshy 的目标多边形数量与 Blender 显示的四边面数都不能直接当作最终三角面预算。工作贴图可保留高分辨率，游戏交付版按实际可见细节缩减。

## 9. 每个资产都能追溯与回退

每个资产使用一张[需求与验收卡](templates/asset-card.md)，记录来源图片、提示词、模型版本、请求参数、任务 ID、消耗额度、原始文件、Blender 修订与最终交付路径。请求记录不包含 API key 或 Authorization 请求头。

推荐目录约定如下，实际制作时再创建：

```text
art/characters/boy/
  references/v001/       独立参考图、提示词
  meshy/v001/            原始结果、脱敏请求参数、任务信息
  blender/               可编辑母版与修订版本
  exports/v001/          已验收 GLB 与贴图
game/assets/characters/boy/  发布给 Godot 的稳定文件路径
```

Godot 工程将来建议放在 `game/`，让母版、历史版本与本地密钥自然处在工程资源目录外。更新时保留游戏引用的稳定路径及导入配置，历史版本在 `art/` 保存。

**API 结果应在完成后及时下载归档。** Meshy 官方当前说明 API 生成资产最多保留 3 天，远端下载链接不能用作项目长期资产库。[官方资产保留规则](https://docs.meshy.ai/en/api/asset-retention)

失败先定位参考图、几何、贴图、绑定还是导出环节；只重做有问题的阶段。记录已经创建的任务 ID，遇到网络超时先查任务状态，避免盲目重复提交同一生成请求。批量生产前先按当时官方定价估算本批额度。[官方定价](https://docs.meshy.ai/en/api/pricing)

## 10. 第一个完整样件的验收

从 **主角 + 树枝 + 一小块玉米地**开始：

- [ ] 四向独立参考图一致；人物视觉符合设计档案。
- [ ] 一个静态模型在目标游戏镜头里通过尺寸、轮廓、颜色与昼夜检查。
- [ ] 骨架在肩肘、胯膝和极限姿势下不出现明显塌陷或穿插。
- [ ] Idle / Walk / Run / Tree Branch Attack 四段可用，走跑无明显脚滑，攻击挂点与握持姿势正确。
- [ ] Godot 中能移动、转向、碰撞、挥树枝；命中时机和动画配合。
- [ ] 更新一次 GLB 后，角色脚本、碰撞体与动画状态机保持有效。
- [ ] 玉米小地块验证遮挡、晃动提示与帧时间，再扩大场景规模。
- [ ] 原始模型、母版、交付 GLB 与记录均在本地可找到。

## 11. 自动化范围与当前状态

已完成：设计与参考图归档、Meshy API 接入、四向独立生产图、模型生成、骨骼绑定与四段动画下载；Blender 5.2.2 和 Godot 4.7.2 已实际运行。完整集成与最终验收结果见[QA记录](qa/first-playable-results.md)。

本轮选择 API 版本归档，不安装 Bridge。游戏的简单四动作切换先使用独立 AnimationPlayer；需要混合树、分层瞄准时再扩展 AnimationTree。

后续适合自动化的环节：提交已确认的资产请求、保存任务 ID、查询状态、下载结果、生成资产记录、检查导出文件。参考图是否一致、儿童动作是否自然、关节变形是否合格、游戏手感是否正确，仍需看实际画面验收。
