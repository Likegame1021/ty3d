# 首个样件执行计划

使用专职代理分工；本计划执行用户已明确授权的可运行样件目标。规格见[首个样件规格](first-playable-spec.md)，制作流程见[资产流程](asset-pipeline-v1.1.md)。

## 任务与交接

- [x] A 主程序：根据规格创建 `game/project.godot`、`game/main.tscn` 与游戏脚本；允许在正式GLB到位前使用明确的临时角色外形，最终须接入真实资产。交付测试命令与结果。
- [x] B 环境 / 技术美术：创建 `game/environment/cornfield.gd` 与模块资产，满足约定接口；交付Blender母版、GLB和环境shader，说明玉米数量与实例化策略。
- [x] C 主美 / 角色资产：从既有角色板生成一致的生产参考图，Meshy生成、绑定、动作；下载归档并在Blender中检查与导出到约定GLB路径。
- [x] D QA准备：将完成条件拆为可执行用例与证据要求；不以文档存在替代运行测试。
- [x] E 集成：接入正式角色，核实动画、比例、手部挂点、碰撞与昼夜；修复脚本和视觉问题。
- [x] F 验证发布：执行headless检查、实际渲染检查、操作回归；提供启动入口、截图与验收结论。

## 验证关注点

- 无效 / 缺失动画不能静默当成已完成；最终明确列出片段名。
- 角色导入后原点、朝向、缩放、右手挂点与碰撞体必须匹配。
- 攻击时窗内多次重叠仍只计一次命中；暂停和重置能恢复状态。
- 玉米扰动可见且不破坏可行走路径；昼夜模式保持主角可读。
- 本机凭据仅由主代理在合适的Windows账户上下文调用官方API，子代理不得读取或转发凭据。
